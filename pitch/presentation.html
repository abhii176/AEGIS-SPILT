Aegis-Split

Money locked. Code proven. Paid.

Escrow for developers. The client funds a milestone. The merge is audited. The payout releases when the code matches the criteria.

Open on the line. Do not start with the stack. One breath, then the problem.

01 · The problem

The freelance deal is still a handshake.

Freelancer Unpaid hours

Work ships. The client goes quiet. The invoice stays open.

Client Prepaid risk

Money goes out first. The build never lands, or it lands broken.

Name both sides. Judges should feel the problem is symmetric, not a freelancer complaint.

02 · What people use now

Slow hands in the middle.

  • 01A person has to approve the work before anyone is paid.
  • 02Escrow sits in a bank queue, with fees and days of float.
  • 03Trust is a support ticket, not a check against the code.

Do not attack a named competitor. The gap is manual release and no link to the diff.

03 · The product

Pay when the diff passes.

Aegis-Split is a micro-escrow for developers, designers, and fast-moving tech clients. PayPal holds the milestone. An auditor reads the git diff against the acceptance criteria.

Financial rails

PayPal Orders lock the funds. PayPal Payouts release them.

Verification

OpenAI or Anthropic when a key is set. Deterministic checks when it is not.

If asked about the model: default OpenAI model in the repo is gpt-4o-mini. The demo still passes with no key.

05 · End to end

Four steps.

FundSarah creates a PayPal order. Capture locks the milestone.
→
MergeRohan links owner/repo and the PR. A merged pull request carries the diff.
→
AuditEach criterion comes back met or unmet, with evidence.
→
PayA pass calls PayPal Payouts. The milestone becomes PAID.

A fail does not release money. Both people get FUNDED, AUDIT_PASSED or AUDIT_FAILED, and PAID.

06 · Judge path

Seven clicks.

  1. 01Seed Sarah and Rohan.
  2. 02Verify government ID and grant monitoring consent.
  3. 03Create the project and the $250 milestone.
  4. 04Fund the vault. Mock capture, or approve in the PayPal sandbox.
  5. 05Link the GitHub repo and pull request.
  6. 06Simulate the merge. Read the pass or fail.
  7. 07Open Released. Status is PAID.

Live command: npm start, then localhost:3000. Demo admin key is hackathon-demo-key. Say that only if they ask.

07 · Architecture

One API. Clear edges.

App

Express serves the demo UI and the API on the same origin.

Data

Postgres through Prisma. Users, projects, milestones, vault funds, merges, notifications.

Money

PayPal Orders to lock. PayPal Payouts to release. Webhook signature check on inbound events.

Code

GitHub webhook, HMAC checked. Merged pull request fetches the diff.

Audit

Criteria parsed into checks. Model when keyed. Heuristics otherwise.

Ship

Docker migrates on boot. Render, Railway, or Fly.

Auth on protected routes is an X-User-Id stub. Say that plainly. Sessions are not the demo.

09 · Trust

No money before identity.

  • IDGovernment ID and monitoring consent are both required.
  • RecordConsent covers on-platform chats and call recordings for a dispute.
  • Fail closedUnmet criteria do not release the vault.
  • Both sidesClient and freelancer get the same funding, audit, and payout alerts.

Keep this concrete. The gate is middleware, not a policy slide.
